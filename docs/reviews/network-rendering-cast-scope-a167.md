# LAN rendering, Chromecast monitoring and group scope · Aurora a167

Video Preview has a destination selector beneath Generate. Director peers advertise via mDNS and exchange profiles over a session-token-authenticated LAN WebSocket. Each queued job captures its destination independently of later selector changes. MiniMax and Flux requests transfer reference media, progress, raw RGB latent banks or image drafts, and final files. The receiving instance uses its own configured models and queue, including the foreign-worker GPU admission from a166. Workspace modes require the corresponding host checkpoint. Server model/runtime paths and credentials cannot be supplied by the caller; transferred conditioning preserves timing and aligned audio/video fields.

Group scope adds All groups / Group N only beside Generate. The same captured request/attachment paths handle local and remote renders. Single-group continuation reads the preceding attachment off the GUI thread, respecting the existing snapped join length, trim origin and workspace mode. Other group authoring and attachments remain intact. A missing required preceding clip prompts an inline status message rather than silently dropping the continuation.

Casting uses Chromecast discovery. Attached videos are served with byte-range support and retain their audio. Live video/Flux monitoring uses a CPU H.264 HLS stream of the displayed preview plus progress/ETA. The normal application player still consumes raw latent frames; the cast encoder runs only while casting. Switching live monitoring sources keeps that stream connected. Tokenized URLs expose only the selected media and generated stream. No player controls are introduced during sampling.

Focused verification uses real WebSockets with fixture inference, asset round trips, mode selection, running percentages/ETA, pending cancellation, session rejection, target switching, a native video-to-Flux workflow and group-only rendering/attachment with untouched other groups. Cast verification uses a fixture receiver with real HTTP range delivery and decodable HLS segments. Live mDNS and profile exchange were checked in both directions between two controllers. Native sampling selection regression remains covered.

Physical device verification: discovered Living Room TV and Living Room TV 2. Living Room TV 2 reported PLAYING for an attached H.264/AAC sample, live render monitoring with 37% / 2m05s, and continuous Flux monitoring with 62% / 18s. The cast session was stopped afterward. This validates device delivery with generated test media, not a billable or live inference run.
