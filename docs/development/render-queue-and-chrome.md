# Integrated chrome, native panel rails and render queue

The approved two-row application header replaces the separate titlebar strip. File commands, Settings, Help and desktop-theme window controls remain on the upper row around a centered, elided project title. Other toolbar actions retain their order on the lower row. Qt system operations handle moving/resizing; close keeps the existing project-save flow. Scope heading styles use packaged assets.

Icon rails preserve each original QDockWidget and its content, native tab relationships, allowed areas, floating features and saved state. Migration backs up the previous window state. Rails are split outside native groups before tabification, and late-created rails use restoreDockWidget before addDockWidget. This avoids treating an outer rail as a content tab or disrupting restored positions. Custom panel headings offer collapse, close and native location/float menus; Effects sizing remains accessible. Reference capability rules apply to both panels and rail icons.

RenderQueue serializes local image/video and cloud image requests through the existing background worker. Request inputs and settings are captured before queuing. Active cancellation waits for the worker acknowledgment, preventing another GPU operation from starting early. Pausing does not cancel the active render. Shutdown cancels queued work and signals active cancellation. Render errors do not interrupt the final close flow; archive-save errors retain their existing close-blocking behavior. Completed jobs release closures and request data, and only bounded metadata history remains in memory. Queue state is session-local.

The queue is a native right-side dock matching the approved proof. Its list delegate paints into the actual viewport rather than fixed-width row widgets. Source text and icons have a dedicated right gutter before the always-reserved scrollbar. Long title/model fields elide; full text and errors are available in details/tooltips. Thumbnail overlays are transient and independent of persistent project status/color.

Artwork callbacks route results to their originating project session and verify the target's prompt/source signature, leaving replacements and edits intact. Completed native video copies attach to the submitted project's metadata; a deleted destination is not recreated. Effects thumbnails share the same queue. Cloud requests already in flight may return before cancellation; cancelled results are not applied.

Validation includes deterministic FIFO/pause/cancellation/failure tests; isolated native window actions, resize centering, narrow/high-text-scale queue layout, native dock collapse/float/move/save/restore and reference capability checks; background image/video project routing; existing editor/core regressions; packaged source/assets, clean installation and published wheel verification. Native compositor drag/resize cannot be established by offscreen tests. Captures use authored demo projects and illustrative progress with a fake executor; no provider/model requests are issued by documentation capture.

Release-candidate verification for 1.13.0a120: 243 release-core tests and 12 subtests passed, including the wrapper for all ten isolated native checks; all 98 isolated editor groups passed after updating the deferred-rename wait and a renamed test import. Five deterministic queue/cancellation tests, ten native chrome/dock/layout/result-routing checks and eight local-generation CPU/UI groups passed. A fresh venv passed dependency checks and the installed native checks. All 462 packaged source/assets matched both the built wheel and the clean installation. No GPU sampling or cloud generation was submitted for these queue/UI checks. The two source icons and both state icons are packaged SVGs.

The publishing workflow remains unchanged. The existing release-core diff test module invokes the isolated native queue/chrome suite, so these regressions run in the established workflow without requiring workflow-file permissions.
