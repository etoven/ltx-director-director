# Aurora a174: batch memory recovery and durable projects

The startup failure was a QVariant conversion overflow: project-card metadata includes unsigned 64-bit MiniMax seeds. Cards now retain a Python mapping rather than converting nested records into signed QVariant integers, preserving the original numeric seeds on disk and in memory.

Resident H3 workers now recompute an absolute device-memory ceiling for each job, including reused checkpoints, instead of retaining a first-job free-memory budget. The budget includes activation estimates, conditioning and a headroom margin. Native CPU/disk offload preserves compatible checkpoint runtimes. Inactive VAE components and accelerator hooks are released after jobs; garbage and allocator caches are reclaimed before worker readiness. Pressure relief also runs at sampling boundaries. Memory accounting appears in existing verbose logs. Recent per-workload activation peaks are kept in a bounded numeric cache. CUDA OOMs retry once with a fresh offloading worker and the same resolved seed, before the queue receives a terminal failure. Recovery applies on the rendering host for remote jobs, and shared reclamation covers Flux.

The queue context menu offers **Render Again** for the clicked job or batch. Repeated batches receive fresh cancellation state, remapped dependencies and a new batch identity; their existing media cache does not substitute completed outputs for new renders. Completed-job replay recipes are retained privately within the queue's existing bounded history and are removed when jobs are swept/deleted.

New Project immediately persists an empty archive, stable identity and placeholder name. Placeholder projects request a short project name within the first successful prompt Generate/Refine response; naming metadata is separated from prompt output and does not require a second provider call. Manual names, project switches and stale naming revisions are respected. Invalid/missing title metadata does not invalidate successful prompt editing. Automatic naming saves accepted content while proposed edits remain in the existing approval flow.

Save All sits beside Save and uses the matching double-disk icon. Dirty open projects are captured and serialized without switching the active workspace. Duplicate requests coalesce; edits made during a save remain dirty. Missing legacy session metadata can be recreated from its saved snapshot. Shutdown reuses this path. A race in opening the closing-progress dialog is fixed: if the last write finishes during its event processing, shutdown proceeds rather than waiting indefinitely at zero outstanding writes.

Focused verification: memory budget/pressure and bounded OOM retry checks; native program startup with the largest unsigned seed, new-project creation, AI naming, Save All across two projects, late edits, manual-name preservation, and zero-save shutdown; queue replay and naming-failure checks. The same focused tests run against the clean-installed wheel. Long GPU/model-quality renders and broad local regression suites are omitted for the requested expedited delivery; broader CI is reported separately.
