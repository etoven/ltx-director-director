# Aurora a176: host renders survive client loss

Accepted network jobs now belong to the host queue rather than a WebSocket connection. Disconnecting a subscriber no longer cancels the render. A stable request ID deduplicates submissions and permits reattachment to the same running or completed job. Bounded host mailboxes retain the latest preview, progress/ETA, recent logs and terminal result without accumulating an unbounded disconnected-client event queue. Explicit cancellation remains a separate protocol operation.

The client durably writes a credential-free recovery receipt before submission and records host acceptance and downloaded results. Receipt recovery also handles a client crash before the next scheduled queue snapshot. Transport reconnection resumes the existing request ID rather than creating another render. On program restart, host discovery probes prior jobs and automatically reattaches to existing work, including live preview and result retrieval, while never-submitted pending jobs stay paused. Completed downloads can be recovered locally. A normal client shutdown detaches its active remote job; it does not send a user Cancel.

Result acknowledgements follow durable local receipt creation. Unacknowledged host results remain available; recently acknowledged jobs are retained in a bounded history. Host process restart is outside this mitigation: the host program must remain running. Updated clients fall back to the legacy protocol when an older host lacks resumable-job support, and existing clients can still submit jobs to an updated host. Both ends need a176 for automatic restart recovery of newly submitted jobs.

Focused verification kills a real client subprocess for both MiniMax video and Flux image requests, confirms host continuation, completes work while offline, injects a subsequent connection loss, retrieves preview/ETA/result without duplicate inference, and verifies explicit cancellation. A native UI workflow closes and reopens the client, recovers from the receipt with the queue snapshot absent, automatically reattaches to the original host job, and retains paused pending work. This is a mitigation for client crashes, not a diagnosis of the remaining crash report. No extended GPU generation is involved; the same focused checks run against the clean-installed wheel and broader CI runs separately.
