# Aurora a180: GUI signal ownership and manual remote Resume

A live two-machine reproduction captured a host SIGSEGV in `Shiboken::Object::cppPointer` while Qt processed deferred QObject destruction. It occurred while a real MiniMax render was active, a second listener with the same hostname appeared, and the client disconnected. The native trace is retained locally, outside the repository. A focused lifetime diagnostic independently showed pool-thread destruction of GUI-affine worker signal objects.

Background signal objects now belong to the GUI callback receiver instead of QRunnable's pool-thread wrapper. Receiver cleanup waits until the worker has returned from signal emission, then destroys both through the GUI event loop. Completed callback references are released. A focused check covers success and failure delivery, forced Python garbage collection, and GUI-thread destruction of every sender.

Manual Resume now treats restored, previously submitted jobs as GUID-only reconnects. It resolves fresh credentials from the listener's instance ID (or exact endpoint), and cannot downgrade an accepted job to legacy/new-render submission because a capability advertisement is incomplete. Never-submitted jobs remain ordinary queued work. The attempt marker is durable for interrupted jobs; terminal entries are not resurrected by that marker. Render Again clears old request/attempt/resume identity and rebinds restored recipes to the new job.

Validation included the actual Resume queue button in a native WebSocket regression, with duplicate host display names, stale capability data, missing local conditioning media, and a fresh listener token. A separate regression covers never-submitted jobs, terminal states, and a fresh Render Again recipe.

The patched source also completed a real cross-machine FL2VA diagnostic render (4 steps, 256 by 256, approximately four seconds). During sampling, a second native Director listener advertised the same hostname using a different instance UUID and port. The client closed and reopened, restored the same job, reattached live latent frames/progress, and exercised Resume queue without submitting a duplicate. The output arrived on the original client queue entry and the host recorded exactly one submission. Neither patched GUI crashed in this run. The secondary instance used independent temporary data/config directories to protect the user's saved queue; concurrent writers to one default queue file are a separate concern, not resolved by listener routing.

The wheel is frozen after these focused checks, verified against source and both installations, and published unchanged. Broader CI is reported separately. Extended investigation and native rendering for this issue were explicitly authorized by the user; no broad unrelated suite ran.
