# Aurora a112: reference-safe prompt completion and MiniMax validation

Unified Prompt Generate and Refine now compare the active reference media, roles and notes against a separate request snapshot before applying a completed response. A changed reference keeps the authored draft and holds the outdated response for review. A fresh request uses the updated references normally. This deliberately avoids restoring the broad editor/model cache fingerprint, which previously rejected valid completions. Standalone text refinement does not use reference conditioning.

The regression covers both Generate and Refine, a reference edit during a request, preserved authored text, retained outdated output and a successful subsequent generation. The original reference regression now starts an actual request to exercise its captured snapshot. All 14 targeted reference/editor checks passed, including normal completion with a ChatGPT model and an obsolete legacy editor fingerprint. The illustrated reference guide and packaged help explain the behavior.

The installed a112 wheel passed both reference-change scenarios, subsequent successful generation, and native video request checks for the unified draft, Reference-panel media, static seed and 960 × 544 / 15-second / 20-step defaults. Archive integrity, worker/source parity, bundled illustrated help and exclusion of private files also passed. Inference modules remain packaged in the wheel and execute through the app's private engine environment.

MiniMax GPU validation passed on the 12 GiB RTX 3060 using the saved unified production prompt and Reference-panel media at 960 × 544, 15 seconds, 20 scheduled steps and RES multistep. The pruned INT8 ConvRot Ref2VA model and NVFP4/AWQ Qwen3-VL encoder loaded successfully. Two complete sampler steps ran without allocation or runtime errors. Both live noisy-latent clips decode all 362 expected frames, vary across the clip and have distinct decoded pixel hashes between steps. No VAE preview decoding occurred during sampling. The test stopped its own worker after the second preview, and the GPU memory was released. This follows the requested first-step VRAM test strategy; final decoded video/audio quality and all 20 steps were not tested.

All five standalone private-runtime CPU checks passed for full-frame noisy previews, clean-estimate cadence, joint audio/video RES trajectories and reset, convolution compatibility and chunked video normalization. An initial CPU harness run incorrectly loaded the repository's GUI fixture into the intentionally isolated inference environment; rerunning these standalone tests with `--noconftest` passed without adding GUI dependencies to that engine. The diagnostic is retained privately. The application-side H3/request/transport checks passed 30 tests, with five optional ML tests skipped there and the relevant numeric tests exercised separately in the private runtime.

Release CI passed all 91 isolated native editor groups, built and published a112. The published wheel also passed archive integrity and parity checks against current UI, inference helpers and illustrated help. Flux and Qwen GPU tests were excluded because the user has already confirmed those pass. This build does not change the sampling or preview implementation from a111. No user project or source model was modified.
